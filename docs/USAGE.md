# Usage — SnipLink

## Shorten a link

1. Open `src/index.html` (or serve `src/` with any static server).
2. Paste a long URL into the **Long URL** field. `https://` is added
   automatically if you leave it out.
3. Optionally type a **custom alias** (letters, numbers, dashes,
   underscores, max 30 characters). Aliases only work through is.gd; if
   the alias is taken, is.gd returns an error and the app falls back to
   TinyURL with an auto-generated slug.
4. Press **Shorten**.

## Copy, QR, health check

- **Copy** — copies the short link to the clipboard.
- **Show QR** — shows a QR code for the short link (generated by
  api.qrserver.com). Press again to hide it.
- **Check link health** — probes the original destination. A response
  means the link looks alive; no response means it may be down (or the
  site blocks cross-origin probes — the message says so honestly).

## History

Every shortened link is stored in your browser's `localStorage` (key
`sniplink-history-v1`, newest first, capped at 50 entries). Each entry
shows the short link, the original URL, and a click counter that increases
when you click the short link in the history list. **Clear history**
wipes the list. History never leaves your device.

## Error messages you may see

| Message | Meaning |
|---|---|
| "doesn't look like a valid http(s) URL" | The input failed validation — check for typos. |
| "is.gd said: … — trying TinyURL…" | is.gd rejected the request (e.g. alias taken); fallback in progress. |
| "Couldn't shorten that link: …" | Both APIs failed — usually no network, or the URL is unreachable. |

## Privacy

The only network requests are: one to is.gd (or TinyURL) to create the
short link, and one to api.qrserver.com when you ask for a QR code.
No analytics, no cookies, no account.
